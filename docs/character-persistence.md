# 人物选择、旧设置与并发保存

更新：2026-11-25。本文件描述当前持久化契约。隔离Rust测试、真实stdio并发和原生桌面已有验证，具体范围见文末；不能推广到任意中断或其他平台。最新整体状态见 [验收状态](character-system-status.md)。

## 文件与锁

- `characters.json` 保存角色注册表及不可变内容修订；新记录包含 `defaultOutfitId`。旧记录缺少该字段仍可读取，从受限大小的已安装 manifest 获取默认服装。
- `character-selection.json` 独立保存人物选择和各人物服装偏好。`settings.json` 对外投影这两个字段，但设置写入不会拥有它们。
- 设置保存、角色选择、包发布和猫咪目录修改共用 `character-import.lock` 的 OS 文件锁。设置保存等待锁，导入/选择沿用忙时返回错误的契约；没有在持锁期间等待应用设置 mutex 的路径。
- 每次设置保存重新读盘，只合并调用方明确列出的字段。桌面、托盘、平台位置保存与 MCP 共 33 处调用已迁移，避免旧内存快照覆盖另一进程刚保存的无关字段。同字段以获得锁后的写入顺序为准。

## 旧猫咪行为

显式选择猫咪（包括重复选择当前猫咪）在共享锁内重新检查猫咪存在性，先保存猫咪设置，再清除人物激活状态。删除猫咪触发的备用猫咪设置仅更新 `catBreed`，保留正在激活的人物；普通猫咪编辑也保留人物。

设置文件与人物选择文件分别原子替换，不构成跨文件事务。如果猫咪设置已保存而清除人物选择失败，返回明确的部分成功错误，人物选择仍可能保留。Windows文件替换与独立stdio并发已有对应证据，尚未覆盖所有中断时刻。

## 更新与失败

包更新移除当前服装时，对外设置投影与播放器都回退到当前包默认服装；原保存偏好不被重写。后续恢复该服装的包版本仍可使用原偏好。缺包或损坏包的错误另由加载链路报告，不能以默认服装元数据代替完整包校验。

保存遇到损坏的现有 `settings.json` 会报错，不用默认设置覆盖原文件。临时文件采用进程号、序号、时间戳和 `create_new`，写入及同步完成后替换；失败现场保留。普通托盘保存失败会刷新内存并记录错误，MCP/命令保存向调用方返回错误。窗口操作、系统自启动等外部副作用不属于文件事务，失败后的真实系统状态仍待原生验收。

## 复现与故障检查

运行入口和独立数据目录见[通用验证说明](character-fixture-validation.md)。静态设置写入审查不替代实际并发测试；Rust库和真实stdio用例分别覆盖设置合并、发布冲突及新进程恢复。当前结果以[验证状态](character-system-status.md)为准。

测试数据位于指定临时目录，发生错误时保留候选和旧修订。正式应用数据中的恢复或清理应先核对注册表、候选generation和资源完整性，不自动删除失败文件。维护文档不依赖任何已删除人物PNG或本机历史日志。
