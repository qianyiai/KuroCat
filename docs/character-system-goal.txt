KuroCat 通用 2D 角色包与 MCP 链路目标

更新：2026-11-25。依据用户最新要求：“不要新建角色”“不用接入人物，把链路打通就行”“为我调整目标”。本目标替代此前批量制作人物和接入当前客户端的计划。

一、最终目标

完成并验证 KuroCat 通用 2D 角色包的 MCP 全链路：
已有素材与完整配置 → 格式校验 → 导入保存 → 激活 → 动作与互动播放 → 换装及旧猫咪切换 → 桌面与 OBS 展示 → 更新与失败恢复 → 重启后恢复。

使用内置大肥鱼素材或通用隔离测试夹具证明链路可用，不新增正式人物，不制作新人物素材，不要求把人物服务接入当前 Codex 会话。

二、实施范围

1. 角色包协议
保存人物身份、作者、来源与许可、格式版本、内容修订、多套服装、资源引用、独立定位、动作、互动、性格和隐私配置。读取完整配置再修改保存不丢字段。导入后由应用保存必需资源，不依赖原素材目录继续存在。

2. MCP 接口
提供并验证 get_character_schema、validate_character_package、import_character_package、get_character_package、list_characters、switch_character、set_character_outfit。支持完整内联配置与 replace 更新。区分校验、保存、导入、激活及运行验证；导入成功但激活失败时分别报告。

3. 通用 2D 运行链路
由共享播放器读取包内动作、互动、性格和服装配置，使用大肥鱼协议作为基准；人物差异由数据控制。服装或修订切换先完成资源解码，处理失败和过期异步结果。桌面、独立菜单、托盘及 OBS 能消费正确的人物、服装和资源。

4. 持久化与兼容
重启恢复人物选择及服装偏好；并发导入、选择和设置保存不互相覆盖；校验失败保留原版本，不暴露半成品。保留旧猫咪 MCP 和设置行为，选择旧猫咪正确退出人物模式，普通设置修改不清除人物选择。

5. 状态、隐私与恢复
桌面和 OBS 处理换装、资源更新、断线及重连；同步必要连续状态。隐私正确抢占动作，退出后不补播旧输入，连续显示状态不包含真实键值。损坏、缺失或不支持的资源返回明确错误；使用健康素材和新修订完成可验证的恢复，不静默覆盖旧修订。

三、完成标准

以真实 stdio/HTTP MCP 客户端验证上述接口及完整流程，使用现有素材核验真实桌面和 OBS 运行。证据覆盖正常导入、完整配置读回、激活与换装、更新、旧猫咪往返、并发保存、失败保留、恢复及重启。

交付源码、角色包与动作协议说明、现有示例/基准使用方式、可复现验证记录和已知限制。静态检查或模拟事件不能冒充真实系统输入、托盘或 OBS 软件验收；未覆盖边界明确记录。

不以新增人物、批量生成素材、连接当前聊天客户端、额外菜单优化或补齐所有硬件组合的人工测试作为本次链路完成的前置条件。实际接入其他人物、客户端配置及额外优化另按用户指令处理。

四、本次不包含

不新增、补全、导入或激活新的正式人物；现有样例和隔离测试夹具仅用于验证。
不制作归档14个人物/21组草稿，不继续雷电将军草图。
不配置当前 Codex 或其他客户端连接，不登录或修改账户。
不实施此前只读排查出的五组额外菜单勾选优化。
真正3D、ZIP导入、语音及其他新功能另阶段处理。

五、授权与保留

沿用已授权的隔离工具链、缓存、本地前端依赖和便携 OBS 做本地验证，不新增全局安装，不提交或推送，不公开发布，不录制或推流，不替换安装版，不自动删除文件或历史现场。

已生成但未导入的雷电将军待机草图保留原位，不继续使用。此前更大的目标文本备份在 tmp/character-system-goal-before-scope-change.txt，仅供追溯，不再驱动当前工作。
